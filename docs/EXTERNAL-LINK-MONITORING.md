# External link monitoring

The standalone workflow runs Tuesdays at 08:17 UTC and can be started from Actions → External link health → Run workflow on main. It is separate from build and deploy; unavailable sites never block publishing. It reads the public-only MDX article directory (including Notion-published MDX), public project links, and public case-study links. It never reads Notion or preview drafts. Markdown links, reference links, and literal MDX `href`/`to` and supported embed `src` are parsed; dynamic expressions and other site source files are outside scope.

HTTP and HTTPS URLs with credentials, query strings, nonstandard ports, or internal site hosts are excluded. Query URLs are excluded from requests as well as reports, preventing tokens from being transmitted. Fragments are removed. DNS responses containing any non-public address are rejected; each request uses a validated resolved IP directly, while TLS still validates the original hostname. Redirects repeat validation. This is a defense in depth boundary, not a general crawler; a destination operating a public proxy is outside its control. Requests send no cookies or authorization, use HEAD with a GET fallback for 405/501, destroy responses without downloading bodies, run sequentially with at least one second per host, and limit redirects to five. A suspected 404/410 or 5xx is checked once more after a delay; 403, 429, and timeouts are not retried. Set `LINK_TIMEOUT_MS` between 1000 and 30000 (default 10000) when running locally.

404/410 are broken; 5xx, DNS failures and redirect loops are potential; 403, 429, timeouts and blocked destinations are inconclusive. Successful permanent redirects are reported separately. A failure or permanent redirect becomes actionable after the same status appears in two consecutive runs. State consists only of hashes and classifications in an Actions cache. Cache eviction or expiration resets the count, so persistence can be delayed. A healthy result resets it and is marked recovered. Network outages may be inconclusive; inspect the artifact before acting.

The report artifact is retained for 30 days. A separate job maintains one open tracking issue only when persistent findings exist; later reports update it, including recovery. Close it once resolved. The issue and artifacts omit URL paths and queries; inspect the referenced file and line to identify the URL. Check the source independently before editing it. Never replace a scholarly source, DOI, or clinical recommendation automatically. A redirect may change meaning or publisher; review it before changing a citation. No article is automatically edited.

To suppress a known false positive, compute `node -e "console.log(require('crypto').createHash('sha256').update('NORMALIZED_URL').digest('hex'))"` using the exact URL without fragment, then add the hash to `scripts/external-links/suppressions.json` in a reviewed PR. Remove it to resume checks. Suppressions should be periodically reviewed. Query-bearing links are not checked even when suppressed. A manual run after a fix updates the report; two runs establish persistence after a cache reset.

If a workflow fails, inspect its job log and artifact availability, verify `npm ci`, main-branch context and Actions cache/issue permissions, and rerun it. The issue job rejects multiple marker-bearing open issues instead of creating more. A manual dispatch and the first scheduled run must be verified on GitHub after merge; the schedule has not yet been observed.
