# External embeds

`<Embed url="https://youtu.be/abcdefghijk" title="A descriptive video title" />` is available to trusted repository MDX authors. YouTube watch links with exactly one `v` parameter, youtu.be video links and youtube-nocookie embed links are supported. Video IDs must be 11 ASCII letters, digits, `_` or `-`. HTTPS, exact hosts, no credentials, unusual ports, fragments, extra query parameters or unsupported paths are required. Inputs are parsed and a fresh `www.youtube-nocookie.com/embed/…` URL is built; other HTTPS URLs receive an external-link fallback. Unsafe URLs display an unavailable message.

Nothing from the provider is loaded before a visitor activates that particular embed. No remote thumbnail, provider script, preconnect, or saved consent is used. Activation is component-local and resets when the component is remounted or the page is reloaded. The original link is in prerendered HTML and opens with `noopener noreferrer` and no referrer; it works without JavaScript. An activated provider can still collect information, including IP address and browser data; privacy-enhanced mode is not a guarantee against tracking. The player receives the site origin, but not the article path, via `strict-origin-when-cross-origin`; YouTube requires an identifying referrer for playback (see [YouTube requirements](https://developers.google.com/youtube/terms/required-minimum-functionality)). Playback may be restricted by the provider, browser, or network; the original link remains available.

The YouTube iframe is cross-origin and sandboxed with `allow-scripts`, `allow-same-origin` and `allow-presentation`, plus fullscreen; no camera, microphone, payment, clipboard, top-navigation or popup permission is granted. Scripts and same-origin together weaken sandbox isolation if framed content ever becomes same-origin with the parent; the canonical hard-coded cross-origin endpoint is therefore part of the security boundary. Do not point it at Simpyll. YouTube functionality with these restrictions requires live provider verification; do not remove restrictions to force playback. No autoplay parameter is set.

Notion public external video and embed blocks pass through the same provider validation. Supported links become `Embed`; unsupported public HTTPS destinations become link-only `Embed` with a sanitized diagnostic. A caption supplies the label, otherwise a generic description is used. Private Notion uploads, unsafe URLs and invalid blocks stop conversion before publication, preserving last-known-good content. No remote HTML is fetched or executed. Manual repository MDX is trusted executable source, not an untrusted sandbox: authors must use this component and must not add raw iframe/JSX from untrusted sources. Notion text is escaped by the importer; do not bypass that conversion.

To approve another provider, document a concrete use case, privacy implications and supported URL shapes; review canonical URL construction, path and hostname validation, sandbox and Permissions Policy, CSP, accessible naming, no-JS behavior, and real provider operation. Add negative URL, import, prerender, hydration, network and browser tests. Until then use the external link. The existing meta CSP enforces `base-uri` and `object-src`; it does not enforce a `frame-src` allowlist. GitHub Pages does not offer repository-controlled response headers; stronger response-header CSP requires different infrastructure. Do not describe a future policy as enforced.
