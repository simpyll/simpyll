# Article section navigation

Ordinary Markdown H2/H3 and the Notion publisher's literal JSX H2/H3 populate
`headings`, a static MDX module export generated by `remarkHeadingIds`. The same
compiler traversal sets rendered IDs. No second renderer, DOM parsing or author
configuration is needed. Inline emphasis, links, code, Unicode and JSON string
expressions contribute text. Arbitrary executable heading expressions and headings
produced at runtime by components are outside this static contract. Headings inside
Disclosure/details retain IDs but are excluded from the TOC because they may be
hidden. The generated GFM footnote label is also excluded. Authors should keep primary sections outside disclosures.

IDs retain the existing lowercase Unicode-letter/number/underscore/hyphen policy;
duplicates use `-1`, `-2`, etc. All literal explicit IDs are reserved before automatic
allocation, as are page landmarks. Existing IDs are preserved except where they
would collide with an explicit ID or landmark. Explicit duplicate or reserved IDs fail compilation with an actionable error. Empty labels become Section.

Articles with fewer than two eligible sections omit navigation. Desktop (80rem+)
reserves a sidebar in CSS from the first HTML paint. The reading column stays 48rem
maximum; narrower viewports use a native collapsed disclosure in a reserved slot.
Its bounded overlay does not push the article or header on expansion. No viewport
branching occurs during hydration. Nested lists represent H3 sections; orphan H3s
stay at the top level. Desktop overflow has a keyboard-focusable region; only its
scrollTop is adjusted when the active link leaves view, never the document scroll.

The scroll spy caches document heading positions on article resize, viewport resize
and font completion. A passive requestAnimationFrame sampler compares scroll position
against those cached values, without measuring headings in the scroll hot path.
The last heading above the shared navigation clearance (+2px tolerance) wins; before
that boundary the first wins, and at document bottom the final section wins. React
state changes only when the selected ID changes. ResizeObserver/listeners/frames
are cleaned up on article changes. Active styles have fixed dimensions and use
aria-current=location, with no live announcements or focus changes during scrolling.

Native fragment links reuse RouteNavigation, its history keys, font/header readiness,
focus and instant scrolling. This also respects reduced motion. The mobile panel
closes before navigation; destination focus is owned by RouteNavigation. No second
scroll handler intercepts links. Existing scroll-margin-top uses Header's measured
--navigation-clearance, including safe areas. No-JS links/disclosure still work; without script, mobile expansion uses normal
document flow so its panel cannot cover the selected section.

Run `npm run lint`, `npm test`, and focused
`npx playwright test article-toc --workers=2`. Browser tests cover desktop/mobile,
keyboard links, history, cold fragments, scroll direction/end, static markup,
geometry, hydration errors and scoped axe checks. Screenshots are in artifacts/toc.
The rich-content isolated fixture also exercises manual + generated Notion headings.
For broken anchors inspect the compiled headings export and generated HTML IDs,
check literal explicit-ID collisions and confirm the heading is outside a disclosure.
Real Android toolbar/compositor, Safari and screen-reader acceptance still require
physical-device/manual testing; Chromium mobile emulation does not establish those.
