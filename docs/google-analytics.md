## Owner setup, in order

1. **GA4 Property ID:** open [Analytics](https://analytics.google.com/), select the correct property, Admin → Property settings → Property details. Copy the numeric Property ID, not the G- stream ID. Check Reporting time zone; changing it later requires review/reset of stored history. Optional: connect Search Console alone by leaving GA4_PROPERTY_ID unset.
2. **GSC property:** open [Search Console](https://search.google.com/search-console), choose the verified property in the selector. Domain property `simpyll.com` uses `sc-domain:simpyll.com`. A URL-prefix property uses its exact URL including scheme and trailing slash (for example `https://simpyll.com/`, only if that is your verified property). Do not choose based on the example. The client accepts this site's Domain and HTTPS apex/www properties; extend the reviewed allowlist if your actual verified prefix differs. Domain metrics include subdomains; confirm this scope is appropriate before publishing.
3. **Google Cloud:** create/select a dedicated project in [Cloud Console](https://console.cloud.google.com/). Note project ID and project number. A project billing account is not required by this implementation; respect the APIs' quotas.
4. **APIs:** enable Google Search Console API (`searchconsole.googleapis.com`), Google Analytics Data API (`analyticsdata.googleapis.com`), IAM Service Account Credentials API (`iamcredentials.googleapis.com`), Security Token Service (`sts.googleapis.com`) and IAM API (`iam.googleapis.com`). The reporting endpoints use `webmasters/v3` and `analyticsdata/v1beta` respectively.
5. **Read-only identity:** IAM & Admin → Service Accounts → create `simpyll-reporting`. Do not grant project Editor/Owner or create a JSON key. Set up GitHub OIDC Workload Identity Federation using the commands below. Bind only this repository's main analytics workflow, not arbitrary branches or repositories.
6. **GA4 access:** Analytics Admin → Property access management → Add users → service account email → Viewer. Do not assign Editor/Administrator. API auth alone does not grant property access.
7. **GSC access:** for the exact verified property, Settings → Users and permissions → Add user → service account email → Restricted. This is read access, not ownership. If your account cannot grant access, ask the verified owner. Do not make the service account an owner to resolve a 403.
8. **GitHub variables:** Settings → Secrets and variables → Actions → Variables. Set `GA4_PROPERTY_ID` (numeric, optional), `GSC_SITE_URL` (exact verified identifier, optional), `GOOGLE_WORKLOAD_IDENTITY_PROVIDER` (full provider resource), `GOOGLE_SERVICE_ACCOUNT` (email) and `GOOGLE_REPORTING_ENABLED=true`. These are configuration, not private keys. Keep `GA4_TRACKING_ENABLED` unset until step 12. WIF needs no stored Google secret. Ensure repository settings allow GitHub Actions to write contents on main; if protected-branch rules reject bot pushes, authorize this workflow under your repository governance or review snapshots through PRs; never force-push or weaken checks casually.
9. **First run:** after merging this PR, Actions → Refresh Google analytics → Run workflow → main. Check out the merged main revision. Schedule is once daily at 10:41 UTC; GitHub may delay scheduled runs.
10. **Confirm responses:** successful source logs say `searchConsole: validated N daily rows` or `ga4: validated N daily rows`. Zero rows can be legitimate for a new property. Source failures log a sanitized message and retain previous history; check property IDs, read permissions and enabled APIs. Auth failures stop before ingestion. No raw API bodies or private diagnostics are uploaded, since artifacts in a public repository are not an owner-only vault. Inspect Google Cloud's access-controlled audit logs for authentication diagnostics.
11. **Confirm deployment:** a changed snapshot is committed to main and explicitly invokes the existing reusable Pages deployment workflow (GITHUB_TOKEN pushes do not themselves trigger push workflows). Wait for deployment, then inspect `/google-analytics.json` and `/pulse`. Each source shows its own refresh date, timezone, status and missing-data notices. A full build is needed because JSON is embedded for static rendering/hydration; unchanged snapshots do not rebuild. Production verification has a separate existing dependency: PR #159 was open at implementation audit and fixes an unrelated breadcrumb assertion. This PR leaves that test untouched. Merge/review #159 separately before interpreting that failure as an analytics regression.
12. **Optional browser tracking:** first review privacy notice, intended audience, data processing/retention, applicable consent requirements and public aggregate disclosure. In GA4 Admin → Data streams → web stream → Enhanced measurement: turn **off all Enhanced measurement**, including the Page views advanced browser-history option, site search and form interactions. Manual page views are the single navigation strategy; `send_page_view:false` disables configuration page views but does not independently disable history-based measurement. Remove any separately installed Google tag/GTM page-view tag. Set GA4 retention deliberately (suggest 2 months for event/user data; aggregate reports and public Git history have different retention). Then set GitHub variable `GA4_TRACKING_ENABLED=true` and run Deploy Simpyll to GitHub Pages on main. Visitors must explicitly choose Allow analytics at `/privacy`; no tag request before that choice. No popup banner is necessary for this strictly opt-in implementation. Decline/withdraw remains available there. Confirm in a normal browser on `https://simpyll.com`: DevTools Network shows no Google request before opt-in, one gtag script after; GA4 Realtime shows initial page view and one per subsequent eligible navigation. Reload/hydration must not duplicate it; query/hash-only changes must not create page views; page_location excludes query/fragment and page_title is the canonical path. Dev/test origins and webdriver do not track. Realtime is separate from delayed Data API reporting. An ad blocker can prevent measurement; the site must continue working. Automated CI mocks do not demonstrate real collection.
13. **Revoke/rotate:** set `GOOGLE_REPORTING_ENABLED=false` to stop jobs; remove service account access from GA4 and GSC, remove WIF binding/provider or disable service account to revoke tokens. Tokens expire automatically; no service-account key to rotate. Set `GA4_TRACKING_ENABLED=false` and redeploy to stop future browser initialization. Visitors can withdraw at `/privacy`; already collected information requires Google-side handling, and public Git history may persist. To clear public data, replace `public/google-analytics.json` with the empty schema and commit/deploy; removing reporting variables alone deliberately retains previous valid history. For incident removal consider repository history and downstream copies.

## Reproducible WIF configuration

Use an authenticated local Google Cloud CLI as a Cloud project administrator. Substitute your **actual** values; do not paste private keys anywhere. These commands create configuration and IAM bindings, not service-account keys. Restrict using immutable GitHub owner/repository IDs from GitHub's repository API; the provider must not trust names alone. The workflow condition also prevents other main workflows from impersonating this identity.

```bash
export ANALYTICS_PROJECT_ID='your-project-id'
export ANALYTICS_PROJECT_NUMBER='your-project-number'
export ANALYTICS_REPOSITORY_ID='actual-numeric-github-repository-id'
export ANALYTICS_OWNER_ID='actual-numeric-github-owner-id'
export ANALYTICS_SA="simpyll-reporting@${ANALYTICS_PROJECT_ID}.iam.gserviceaccount.com"
gcloud services enable searchconsole.googleapis.com analyticsdata.googleapis.com iamcredentials.googleapis.com sts.googleapis.com iam.googleapis.com --project="$ANALYTICS_PROJECT_ID"
gcloud iam service-accounts create simpyll-reporting --project="$ANALYTICS_PROJECT_ID" --display-name='Simpyll read-only reporting'
gcloud iam workload-identity-pools create simpyll-github --project="$ANALYTICS_PROJECT_ID" --location=global --display-name='Simpyll GitHub analytics'
gcloud iam workload-identity-pools providers create-oidc github --project="$ANALYTICS_PROJECT_ID" --location=global --workload-identity-pool=simpyll-github --issuer-uri=https://token.actions.githubusercontent.com --attribute-mapping='google.subject=assertion.sub,attribute.repository_id=assertion.repository_id,attribute.repository_owner_id=assertion.repository_owner_id' --attribute-condition="assertion.repository_id=='${ANALYTICS_REPOSITORY_ID}' && assertion.repository_owner_id=='${ANALYTICS_OWNER_ID}' && assertion.ref=='refs/heads/main' && assertion.workflow_ref=='simpyll/simpyll/.github/workflows/google-analytics.yml@refs/heads/main'"
gcloud iam service-accounts add-iam-policy-binding "$ANALYTICS_SA" --project="$ANALYTICS_PROJECT_ID" --role=roles/iam.workloadIdentityUser --member="principalSet://iam.googleapis.com/projects/${ANALYTICS_PROJECT_NUMBER}/locations/global/workloadIdentityPools/simpyll-github/attribute.repository_id/${ANALYTICS_REPOSITORY_ID}"
```

The provider variable is `projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/simpyll-github/providers/github`. No project data role or Token Creator role is needed for this standard WIF service-account impersonation flow. Granting the service account GA4/GSC permissions is still required. Organization policies can require an administrator's help.

For local ingestion use a short-lived OAuth access token with `webmasters.readonly` and/or `analytics.readonly` scope for an identity authorized on the configured properties, supplied via `GOOGLE_ACCESS_TOKEN` in your shell environment. Do not print it, commit an env file, or put it in a command shared publicly. Run `npm run ingest:analytics`; tests/build need no credentials. Local tools do not create a key fallback.

## Contracts, persistence and calculations

- Separate versioned `/google-analytics.json` contract alongside the existing `/pulse.json`; no changes to the established content/health serializer. Imported JSON renders with the existing lazy Pulse route, preserving SSR and identical hydration. A public JSON snapshot is a deployable artifact, never a raw API response.
- GSC: one bounded 365-day date-dimension, finalized web-search report. Search dates are Pacific calendar dates. GA4: one bounded 365-day date report with official `activeUsers`, `sessions`, `screenPageViews`, `engagedSessions`, `userEngagementDuration`; property timezone is read from response metadata, not inferred. The four-day lag is conservative for both clocks. Missing rows remain missing. GA4 history does not imply collection before installation.
- Two requests/day, up to four attempts each for transient network errors, timeouts, HTTP 429/5xx; bounded Retry-After/exponential delay, 30-second request timeout. Permanent 4xx are not retried. Reports with thresholding, sampling, other-row loss, truncation or bad fields are rejected, preserving prior valid data. No API call during visitor loads.
- Success replaces the whole requested window to handle corrections/removals, preserves earlier history up to 730 calendar days, validates strict recursively allowlisted public fields, sorts rows deterministically and atomically renames a temporary snapshot. Duplicate dates/negative or invalid counts fail validation. No fake zeros, query/page dimensions, identifiers, segments, secrets or diagnostics. A temporarily failing source retains history and marks error. Successful empty reports replace that window with empty history. A changed refresh date is a real snapshot change even if counts are unchanged; repeated same-day identical runs are no-ops.
- Historical snapshots are committed on main, not left on ephemeral runners. A concurrent main push rejects this job's push; rerun on the new main or wait for the next schedule. No force push/rebase of unvalidated data. Pages uses its established deployment concurrency; Notion and analytics only add their own paths. Stale data is labeled after seven days at runtime without hydration changes.
- Charts provide discrete daily points (missing dates are not connected/interpolated), explicit axes and data tables. Timezone/refresh/end dates belong to each source. Comparisons require every date in both periods, so partial windows never imply complete traffic. CTR = sum clicks / sum impressions. Position = sum(position × impressions) / sum impressions. Sessions/views sum across days; engagement uses aggregate seconds/sessions and engaged sessions/sessions. Daily distinct active users are **never** summed into period unique users. Percentage change from a zero baseline is unavailable. Lower numerical position is better; the axis is ordinary ascending and explicitly labeled.
- Page-level Top Content remains intentionally omitted: small-site minimum-count disclosure needs owner privacy approval. No raw query/page report is requested. This optional breakdown cannot leak unpublished URLs.
- Basic consent mode, no tag before affirmative consent. Advertising consent always denied. The production deployment variable is separate from reporting authorization. Manual page views allow only known public routes and published articles, strip query/hash, avoid raw title/referrer, deduplicate consecutive canonical routes, skip unknown/private paths and pause Google on ineligible routes. Consent preferences are local; withdrawal deletes accessible `_ga` cookies and disables the loaded library. Subsequent opt-in restores it. SSR imports never read browser globals.
