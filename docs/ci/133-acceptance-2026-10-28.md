Only validation's `validate` is the intended aggregate merge context. Performance is
outside its needs list; a performance failure can make the whole manual workflow
red while aggregate succeeds. PR browser/fixtures/performance skips are policy,
not passing execution. Cancelled/superseded runs are not acceptance; check the current
head. Deployment is gated by its build, not by a validate workflow on main (there is
no main-push validation event). Merge protection is therefore operationally essential.

npm caches hold downloads, never node_modules. Image keys include OS, lockfile,
generator/media/content inputs; image generator verifies fingerprints and variant
sizes and repairs missing outputs. No compiled HTML cache crosses revisions. PR
merge-ref caches cannot be restored by main; same-run artifact scope and read-only
PR permissions prevent a privileged consumer from executing PR output. Build variants
used by synthetic fixtures must rebuild their own input; their sequential isolation
is intentional. The deployment rebuild is intentional: PR merge revision and runtime
configuration may differ from the exact main/content revision.
